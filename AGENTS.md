# AGENTS.md — ОргДифф (кейс 11 HackAlem AI, 23.09.2026)

## Что мы строим
Агент сравнения оргструктуры и функционала: загружаются документы «до» и «после» реорганизации (.docx: положения, ДИ, приложения к приказам) → агент находит изменённые подразделения, сопоставляет функции, показывает потери, дубли и конфликты интересов → заключение, где каждый вывод подтверждён документом и пунктом. Спецификация — `docs/spec-case11.md` (источник истины), обязательные условия — `docs/case.md` (приоритет над всем), матрица владения файлами — `docs/sessions.md`.

## Архитектура
- `backend/` — FastAPI, Python 3.12, uv. `app/parse` (docx → пункты), `app/units.py` (подразделения до/после), `app/functions.py` (функции с пунктами), `app/matching.py` (до↔после), `app/duplicates.py` + `app/rules/conflicts.py` (дубли, конфликты интересов), `app/conclusion.py` + `app/export_md.py` (заключение), `app/pipeline.py` (оркестратор шагов, фоновая задача), `app/routers/runs.py` (API), `app/llm.py` (OpenAI Responses API, Structured Outputs strict, mock-режим), `app/prebuilt/` (раскрытые заготовки, см. NOTICE.md), `app/mocks/` (фикстуры по имени вызова и хэшу входа).
- `frontend/` — Next.js App Router, TypeScript, Tailwind, русский UI: `/` загрузка, `/runs/[id]` прогресс, `/report/[id]` вкладки Подразделения / Функции / Дубли и конфликты / Заключение, панель источника.
- Запуск `make dev`; проверка `scripts/check.sh` (ruff, pytest, eslint, tsc, build).

## Жёсткие правила
1. **Каждый вывод — с источником** `{doc, version, clause_number, quote}`. Находка без источника не показывается. Номера пунктов проверяются по документу кодом; выдуманные отбрасываются.
2. **Детерминированное — код, LLM — только языковые шаги** (извлечение функций, сопоставление остатка, объяснение, заключение), всегда через `app/llm.py` со строгой JSON-схемой.
3. **Mock-режим обязан проходить весь сценарий на тестовом комплекте** `data/case11/` без ключа: эксперт проверяет без своих аккаунтов. Фикстуры — реальные ответы модели, сохранённые в файлы. В live-режиме заглушек нет.
4. **Секреты** только в `.env`. Никаких ключей в коде, логах, фикстурах.
5. **Владение файлами**: пиши только в файлы своей строки `docs/sessions.md`. `backend/app/main.py`, `backend/app/schemas.py`, `frontend/app/layout.tsx` закрыты после волны 1. Чужие тесты не править.
6. **Ошибки** — JSON `{error, detail}` с понятным русским текстом; вход валидируется (только .docx, ≤10 файлов, ≤10 МБ); процесс не падает.
7. **Git**: коммиты каждые 20–30 минут на своей ветке `s/*`, conventional commits, никакого force-push, в `main` мержит только интегратор B (`scripts/ops/merge-train.sh`). Коммит из Codex-сессии несёт трейлер `Co-authored-by: Codex <noreply@openai.com>` (хук `scripts/hooks`).
8. **Без новых зависимостей.** Есть: fastapi, pydantic, openai, pandas, numpy, python-multipart, httpx, pytest; next, react, tailwind.
9. **Никаких утверждений в README и заключении, которых нет в коде и данных.** Раздел «Раскрытие» README перечисляет заготовки (каркас, `app/prebuilt`, тестовые документы организаторов, промпты) — ничего из него не удалять.
10. `CLAUDE.md` в репо не создавать: Claude Code читает этот файл.

## Как добавлять шаг пайплайна
Схема ответа (pydantic + JSON-схема strict в `app/llm_schemas.py`) → промпт в `app/prompts/<name>.md` → функция в своём модуле с валидацией `clause_number` → mock-фикстура для тестового комплекта → тест в mock-режиме → регистрация в `app/pipeline.py` (только владелец S08/S14) → `scripts/check.sh` → коммит.
