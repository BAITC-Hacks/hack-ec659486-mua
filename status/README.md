# status/ — журнал команды и вердикт тайм-кипера

Две вещи, обе в репозитории (это и есть «подтверждаемый результат каждого часа» по п. 6.6 Положения):

- `status/log-A.md`, `status/log-B.md` — каждый участник **каждые 20 минут** со своего ноутбука: `scripts/check.shin WHO=A DONE="парсер grades.csv" DOING="features.py" BLOCK="-" ETA=14:10`. Скрипт дописывает строку в файл этого человека в корневом worktree (main), коммитит и пушит — так второй ноутбук и таймкипер видят чекин через GitHub. У каждого свой файл, поэтому rebase никогда не конфликтует. Без сети коммит остаётся локально и уйдёт со следующим push.
- Отчёты аудита и прогонов допуска лежат **не здесь**, а в orphan-ветке `ops/audit` (`scripts/ops/init-ops-branch.sh`, затем `scripts/ops/audit.sh prep` / `scripts/ops/audit.sh save HHMM`). В `main` они не мержатся.

Формат строки лога (одна строка, без переносов):

```
| 14:00 | A | done: парсер grades.csv, тесты | doing: features.py | block: - | eta: 14:20 | s/backend@3f2a1c |
```

Правила: пропущенный чекин — тоже сигнал; «block» держится дольше 10 минут — зовём второго; таймкипер не спорит, а называет конкретный пункт плана и что вырезать.
