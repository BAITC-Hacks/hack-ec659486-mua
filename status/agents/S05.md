## Как устроено (для соседей S08, S09, S15)

- `detect_units(doc_before, doc_after, llm=None) -> UnitsResult`. `UnitsResult` — это `list[UnitChange]` (годится прямо в
  `Report.unit_changes`, проверено `TypeAdapter`) плюс атрибуты `units_before`, `units_after` (`list[Unit]`) и
  `positions_before`, `positions_after` (`list[Position]`: `name`, `version`, `clause_numbers`, `sources`) — S09 берёт их как `executor`.
- Порядок: `find_candidates(doc)` (словарь + аббревиатуры в скобках + `section_path`/`lead_in` + вложенные по номеру пункты;
  «управление»/«группа» — только с заглавной буквы, чтобы «управление рисками» не шумело) → `extract_units` (LLM на разделе
  «Структура»: элемент `section_path` начинается с «3.» или содержит слово «структура»; нет раздела — весь документ) →
  `match_units` (совпадение нормализованного названия или аббревиатуры → kept без LLM; LLM только если остаток есть с обеих сторон).
- Проверки кодом: `clause_number` из ответа — только из переданных пунктов, чужие отбрасываются с `logger.warning`; подразделение
  без валидных пунктов и «подразделение», оказавшееся должностью («Главный аудитор»), отбрасываются; пары `match_units` — только
  имена из переданных списков и согласованный статус (created без before, abolished без after); чего модель не покрыла — честно
  created/abolished.
- `Unit.sources` = пункты из ответа модели + пункты словарного кандидата с тем же названием/аббревиатурой; `UnitChange.sources` —
  объединение обеих сторон. Цитата — дословный префикс текста пункта ≤ 300 символов. `Unit.parent` — `Unit.id` родителя.
- Для S09: нормализация названий — `app.units.normalize_name`, аббревиатура — `app.units.abbreviation_of`.
- Mock: `mocks/<name>/<sha256(json.dumps(payload, ensure_ascii=False, sort_keys=True))[:16]>.json`; нет файла → `LLMError`
  «нет mock-фикстуры для 'extract_units': ожидался файл mocks/extract_units/<hash>.json …» (S08 покажет это как ошибку шага).
- Для S15: `LLM_MODE=live LLM_RECORD_MOCKS=1` — живые ответы `extract_units`/`match_units` пишутся в те же файлы по хэшу,
  правка кода не нужна. Путь к фикстуре для своих docx: `uv run python -m app.units до.docx после.docx` (нужен влитый S04).

## Что не сделано и почему

- `data/case11/*.txt` в репозитории нет, а `data/` не моя зона. Тест строит `Document` из `data/case11/*.docx` тем же путём,
  что запасной разбор `prebuilt/lib_docx` (zip + xml), по правилам S04 (номер, буквенный подпункт `3.4.а`, `section_path`, `lead_in`).
- Фикстуры написаны вручную в формате живого ответа модели (ключа в сессии не было). Их заменит S15.
- Если S04 поменяет текст пунктов до мержа, хэши входа изменятся и в mock-режиме будет `LLMError` с именем нового файла.
  Тогда достаточно скопировать тот же JSON под новое имя: номера пунктов в ответах совпадают, у S04 те же `3.4.а`, `3.6.г`.
- `transformed` с пустым `after` означает разделение или слияние без единственного преемника, детали в `note`. Так задано в промпте
  `match_units`, чтобы ДИТААД и ДОА остались `created`.
- У БВА `UnitChange.sources` большой (≈340 пунктов: всё, где упомянут БВА). Нужен свёрнутый список в UI (S07/S12).
