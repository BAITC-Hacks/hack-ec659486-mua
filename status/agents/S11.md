## Как устроено

**Дубли.** Кандидаты: `candidate_pairs` от S08 → иначе ленивый `app.candidates.find_duplicate_candidates(functions)` →
при `ImportError` запасной генератор по равенству сигнатуры с `logger.warning("app.candidates недоступен, кандидаты только по сигнатуре")`.
Код отсекает до LLM: запреты, шаблоны (`TEMPLATE_PHRASES` + «иные/другие/прочие функции/поручения»), участие/содействие/соисполнитель,
пары внутри одного подразделения; не больше 5 кандидатов на функцию. Затем `verify_duplicates` — по вызову на пару, лимит 200.
`is_duplicate=true` принимается только при `same_action`, `same_object`, `both_executors` = true; иначе, как и при `LLMError`
или лимите, — `verified=False`, `verification_note="требует проверки: <причина>"`. `is_duplicate=false` — пары нет.
Подтверждённые идут первыми (`dup-1…`).

**Конфликты.** Только одно подразделение и один объект (перекрытие объекта ≥ 0,6; главное слово объекта — первое
существительное, не прилагательное). Strong — утверждает/подписывает/контролирует/проверяет/аудирует; weak — согласовывает
(не находка). Правила `RULES`: (a) исполнитель+контролёр, (b) инициатор+утверждающий, (c) аудитор+оператор (закупки,
начисления, учёт, договоры, платёжные документы; запрет-мандат 5.8.1 прикладывается источником), (d) самоконтроль,
и дополнительно (e) «запрет+исполнение» — функция делает то, что прямо запрещено `constraints` («не имеют права …»).
Исключения: «на согласование/утверждение», контрольное слово в названии документа, участие/содействие/соисполнитель,
«организация и контроль» (в т.ч. «организует X» + «контролирует X» в разных подпунктах), надзор за чужим исполнением,
собственный план и отчёт, ссылка на документ. Запрет стороной (a)–(d) не бывает («не имеют права инициировать и
утверждать транзакции» — не находка; тот же текст как обязанность — правило b).
`explain_conflict` на каждую находку: `verified=true` → подтверждено; `verified=false` → кандидат с примечанием модели;
`LLMError` → «требует проверки: объяснение не получено (…)», объяснение собирается кодом из правила и дословных цитат.
Номера пунктов в `explanation`/`verification_note`, которых нет среди пунктов находки, удаляются кодом.

## Что не сделано и почему

- Контракт закрыт: у `Duplicate` нет полей `verification` и `sources`, у `Conflict` нет `verification`. Источники дубля —
  `function_a.sources` + `function_b.sources` (их и проверяет `_sourced` в `pipeline.py`); вид проверки записан текстом:
  `Duplicate.note` начинается с «Проверка: llm» / «Проверка: lexical», у конфликта `verified` + `verification_note`.
  Интегратору: если поле `verification` нужно в UI — добавить в `schemas.py`/`types.ts`, модули заполнят без переделки.
- Фикстуры для реальных функций тестового комплекта не записаны: хэш payload зависит от вывода S09 (id, тексты, исполнители).
  S15 при живом прогоне с `LLM_RECORD_MOCKS=1` сохранит их в `mocks/verify_duplicates/` и `mocks/explain_conflict/` без правки кода.
- Имена подразделений S08 не передаёт (`Function.unit_id` — непрозрачный id), поэтому «подразделение аудита» (правило c)
  определяется по исполнителю/id («аудит», «БВА»), а самоконтроль (d) по названию — только при `unit_names`.
  Интегратору: в `pipeline._conflicts` можно передать `unit_names={u.id: u.name}` ключевым аргументом.
- `app.candidates` (S10) и `app.llm_schemas` (S13) в ветке ещё нет: импорт ленивый, модели `VerifyDuplicatesOut` /
  `ExplainConflictOut` берутся из `llm_schemas`, если он есть, иначе свои с `extra="forbid"`. Формат пар от S10
  принимается любой разумный: `(a, b, score)`, `(a, b)`, dict/объект с `a/b` или `function_a/function_b`, функции или id;
  оценка вне 0..1 заменяется лексической.

## Совместимость с S13 перед поездом волны 3 (A, 15:50)

В совместном прогоне с `s/schemas` падали 2 теста S11 (`test_inconsistent_llm_answer_stays_unverified`,
`test_fixtures_have_live_answer_format`). У `VerifyDuplicatesOut` в `app.llm_schemas` есть валидатор

валидатора. Правило согласованности проверяет сам S11, итог тот же — «требует проверки». С S13 и без него
`tests/test_conflicts.py` зелёный. `ExplainConflictOut` по-прежнему берётся из `app.llm_schemas`.
