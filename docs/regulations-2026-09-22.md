## 2. Что изменилось по существу

### 2.1. Заготовки прямо разрешены — 5.4.4.2 (НОВОЕ, в нашу пользу)

> «Командам разрешается использовать заранее подготовленные технические компоненты, инструменты
> разработки, собственные библиотеки, шаблоны и инфраструктурные решения, если они не являются
> готовым продуктом или основной частью решения, представляемого на Хакатоне. Основная
> функциональность Проекта, соответствующая Задаче Хакатона, должна быть разработана в рамках
> Соревновательной части.»

Дополняется 5.4.4 (раскрывать сторонние материалы: open source, библиотеки, модели, датасеты,
шаблоны) и 5.4.5 (нельзя сдавать ранее созданный готовый продукт, который **до старта обладал
основной функциональностью**).

**Следствие.** Каркас, Docker, CI, обёртка над LLM — легальны без оговорок. Формулировка
«вся доменная логика написана во время хакатона» больше не нужна и остаётся ложной: наши
каркас и внутренние утилиты разбора документов сделаны заранее.
Правильная стратегия по новой редакции: **перечислить заготовки прямо**, а не утверждать, что их нет.

### 2.2. Не запускается по README — не допущены. Без исправлений — 5.4.16 и 5.6.5 (НОВОЕ)

> «Если итоговую версию Проекта не удаётся запустить по инструкциям, размещённым в Репозитории,
> Команда не допускается к дальнейшему отбору. Дополнительные пояснения и исправления не принимаются.»

**Это главное изменение дня.** Воспроизводимость перестала быть строкой на 20 баллов и стала
условием допуска. Старый пункт 6.12 позволял экспертам запросить пояснения по запуску — теперь нет.

### 2.3. README — обязательный состав, 5.4.15 (НОВОЕ)

Обязаны присутствовать восемь пунктов:
описание решения и его назначения · описание архитектуры · используемые технологии ·
инструкции по установке · инструкции по запуску · необходимые зависимости ·
параметры окружения · **порядок проверки основного сценария работы**.

5.6.4 добавляет: пошаговая инструкция с системными требованиями и переменными окружения.

### 2.4. Проверка без личных аккаунтов — 5.6.6 (НОВОЕ, бьёт в нашу архитектуру)

> «Команда обязана обеспечить возможность проверки ключевой функциональности Проекта без
> необходимости использования личных аккаунтов участников, персональных подписок или закрытых
> учетных записей. В случае использования внешних сервисов, API или иных инструментов команда
> обязана предоставить необходимые демонстрационные доступы, тестовые учетные записи либо иные
> способы проверки работы решения.»

У эксперта не будет ключа OpenAI. Значит `LLM_MODE=mock` должен проходить **весь основной
сценарий**, а не только пример, и это должно быть написано в README как штатный способ проверки.
Mock перестал быть удобством и стал требованием.

### 2.5. Репозиторий — 5.4.9, 5.4.11, и DQ по 5.9.2

Основная разработка — **исключительно** в GitHub-репозитории команды, созданном организатором
через платформу. Сторонние закрытые репозитории для основной разработки, хранения кода Проекта
либо передачи финальной версии не допускаются. В репозитории должна быть подтверждаемая история
разработки. Её отсутствие — прямое основание для дисквалификации (5.9.2).

Импорт заготовок это не запрещает (5.4.4.2), но вся работа 13:00–18:00 — только там.

### 2.6. Почасовой результат — 5.4.8 (мягче по форме) и 5.9.2 (жёстче по санкции)

Промежуточным результатом теперь может быть: изменения в коде или репозитории, разработанный
функционал, прототип, дизайн, **схема архитектуры**, настроенная модель, проведённое тестирование,
подготовленные данные или иное подтверждение фактического прогресса.

Но: «отсутствие у команды подтверждённого промежуточного результата по итогам **любого**
отчётного часа соревновательной части» — первое в списке оснований для дисквалификации (5.9.2).

### 2.7. Критерии техотбора ушли в ТЗ задачи — 5.5 (ВАЖНО)

> «Техническая оценка каждого Проекта осуществляется в соответствии с требованиями, критериями
> оценки, правилами начисления баллов и иными условиями, установленными в **техническом задании
> соответствующей Задачи**.» (5.5.1)
> «При оценке Проекта применяются исключительно условия и критерии, опубликованные для
> соответствующей Задачи **до начала Соревновательной части**.» (5.5.3)

Рубрики 20/25/20/20/15 в Положении больше нет. Наш README-шаблон построен под неё — он целится
в документ, которого больше не существует. Реальные критерии — в ТЗ трека, и по 5.5.3 они должны
быть опубликованы **до 13:00**, то есть потенциально уже сегодня.

### 2.10. Оборудование — 5.2.8 (НОВОЕ требование)

Участники самостоятельно обеспечивают себя ноутбуками, зарядными устройствами, ПО, учётными
записями, **переходником с LAN-подключением, совместимым с используемым ноутбуком**, и иным
оборудованием.

Раньше этого пункта не было. Проводная сеть — вероятно основной канал в зале.

### 2.11. Выход с площадки — 5.1.7.1

Временный выход — **только с предварительного разрешения Организатора**, суммарно не более
60 минут. Превышение без согласования — основание для дисквалификации. Исключение — экстренные
обстоятельства (5.1.7.2) с уведомлением при первой возможности.

### 2.12. Питание — 6.3.5 (НОВОЕ)

Организатор даёт каждому участнику 4 комплекта бутербродов и 3 литра питьевой воды. Своя еда
разрешена, но не скоропортящаяся и без резкого запаха. 
утверждает обратное со ссылкой на старый 15.3 — устарел.

### 2.13. Дедлайн — 5.4.13, 5.4.14

18:00 — официальный момент окончания; итоговой считается версия, зафиксированная организатором
на этот момент, **независимо от того, когда фактически заблокируется интерфейс платформы**.
Изменения после окончания соревновательной части при оценке не учитываются.

### 2.14. Интеллектуальная собственность — 6.1.2–6.1.4

Участники предоставляют организатору право использования результатов безвозмездно, без
ограничения по территории и сроку, включая воспроизведение, публикацию, модификацию, адаптацию,
распространение и **передачу третьим лицам**. Знать до того, как класть в репозиторий что-то своё
ценное.

### 2.15. Апелляций нет — 5.10.3, 5.10.4

Повторная оценка и пересмотр профессионального суждения экспертов или жюри не предусмотрены.
Представление доработанной версии после завершения этапа основанием для пересмотра не является.
Исправляются только подтверждённые арифметические, технические и редакционные ошибки (5.10.6).

### 2.16. Правила больше не изменятся — 6.4

После начала соревновательной части ретроспективное изменение обязательных требований, критериев
технической оценки и порядка технического отбора не допускается. Сегодняшняя редакция — последняя.

## 3. Что из этого следует для нас

1. **Воспроизводимость — не баллы, а допуск.** Чистый прогон `git clone` → README → работает,
   на втором ноутбуке, в пустом окружении. Единственный блок дня, который нельзя сократить.
2. **Mock-режим обязателен по 5.6.6** и должен проходить основной сценарий целиком.
3. **Раскрытие переписать под 5.4.4.2** — перечислить заготовки, а не отрицать их.
4. **Критерии — в ТЗ трека 07**, не в Положении. Прочитать до старта.
5. **LAN-переходник** — в сумку, на оба ноутбука, проверить заранее.
6. **Почасовой результат** — достаточно схемы архитектуры или подготовленных данных, но пропуск
   любого часа — основание для дисквалификации.
7. **Ссылки на пункты** во всех наших документах переписать по таблице из раздела 1.
