# S04 — Разбор .docx в пункты (волна 2, 14:40–15:20, A, ветка `s/parse`)

Прочитай `AGENTS.md`, `docs/case.md` (обязательное условие 4 — источник для каждого вывода), `docs/spec-case11.md` §2 строка P1 и §3 (Document, Clause). Модели `Document`, `Clause` бери из `backend/app/schemas.py` (сделано S01; если в твоей ветке их ещё нет — `git fetch origin s/contract && git show origin/s/contract:backend/app/schemas.py`, но сам файл не правь).

**Пишешь только в:** `backend/app/parse/__init__.py`, `backend/app/parse/docx.py`, `backend/tests/test_parse.py`.
**Не трогаешь:** `main.py`, `schemas.py`, `llm.py`, `prebuilt/*`, роутеры, фронт. Новых зависимостей нет: python-docx не установлен, `prebuilt/lib_docx.para_objs` сам падает на zip+xml — этого достаточно.

Задача: детерминированный шаг P1. Из `.docx` — список `Clause` с номером пункта, заголовком раздела и порядковым индексом, чтобы все следующие шаги (P2–P6) ссылались на пункт, а не на «где-то в документе». LLM здесь не используется.

Сделай:
1. `parse/docx.py`: `parse_docx(path, version: "before"|"after", name: str | None = None) -> Document` и `get_clause(doc, number) -> Clause | None`. Абзацы — только через `prebuilt.lib_docx.para_objs(path)`; таблицы уже приходят строками (через табуляцию) — оставляй их как пункты без номера.
2. Номер пункта — регулярка по началу абзаца: `1.`, `1.2.`, `1.2.3.` (после номера пробел или конец). Уровень — число сегментов. Абзац без номера — `number=None`, текст приклеивается к разделу как самостоятельный пункт (не сливай с предыдущим: цитата должна совпадать с документом дословно).
3. Заголовок раздела: абзац с номером первого уровня (`3.`) и коротким текстом (≤ 120 символов, без точки в конце или заглавными) открывает раздел; `Clause.section` у всех последующих — его текст, например «3. Структура и организация работы внутреннего аудита». До первого раздела — `section="Преамбула"`.
4. Оглавление отбрасывать: в конце документа идут строки вида «1. ОБЩИЕ ПОЛОЖЕНИЯ 1», «14. ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ 34 ОГЛАВЛЕНИЕ 38 ПРИЛОЖЕНИЯ 38» — заглавный текст с числом страницы на конце после уже пройденного раздела с тем же номером. Такие строки в `clauses` не попадают. Проверь на `data/case11/*.txt` — это те же docx текстом.
5. Версия: аргумент `version` обязателен; `name` по умолчанию — имя файла; `kind` — по имени файла («положение» → `polozhenie`, «должностн» → `di`, «приказ» → `order`, иначе `other`). `id` — стабильный: `sha1(содержимого файла)[:12]`.
6. Не `.docx` (`.pdf`, `.xlsx`, `.txt`) → `ValueError("формат не поддержан в прототипе: .pdf")`; пустой или битый файл → `ValueError` с понятным текстом. Никаких молчаливых пустых `Document`.
7. `tests/test_parse.py` на обеих редакциях из `data/case11/`: ≥ 300 пунктов с номером; `get_clause(doc, "1.4")` найден и содержит «Главный аудитор»; есть раздел, начинающийся с «3. Структура»; ни у одного пункта текст не оканчивается на пробел + число страницы и нет текста «ОГЛАВЛЕНИЕ 38»; индексы строго возрастают; `parse_docx("x.pdf", "before")` → `ValueError` с «не поддержан».

**Done-when:** `cd backend && uv run pytest -q tests/test_parse.py`
**Cut-if:** `kind` всегда `other`; уровень пункта не вычислять.

В конце выведи список изменённых файлов и вывод Done-when.
