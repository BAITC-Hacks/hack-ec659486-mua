Задача: детерминированный шаг P1. Из `.docx` — список `Clause` с номером пункта, заголовком раздела, порядковым индексом и контекстом пункта (`section_path`, `lead_in`, `modality`), чтобы все следующие шаги (P2–P6) ссылались на пункт, а не на «где-то в документе», и видели, кто и в каком режиме (обязанность / право / запрет) его выполняет. Пункт «5.9.1. выполнять функциональные обязанности…» сам по себе читается как функция, и только вводная «5.9. … не имеют права:» делает его запретом — без контекста такие пункты попадут в потери и дубли. LLM здесь не используется.

Сделай:
1. `parse/docx.py`: `parse_docx(path, version: "before"|"after", name: str | None = None) -> Document` и `get_clause(doc, number) -> Clause | None`. Абзацы — только через `prebuilt.lib_docx.para_objs(path)`; таблицы уже приходят строками (через табуляцию) — оставляй их как пункты без номера.
2. Номер пункта — регулярка по началу абзаца: `1.`, `1.2.`, `1.2.3.` (после номера пробел или конец). Уровень — число сегментов. Абзац без номера — `number=None`, текст приклеивается к разделу как самостоятельный пункт (не сливай с предыдущим: цитата должна совпадать с документом дословно).
3. Заголовок раздела: абзац с номером первого уровня (`3.`) и коротким текстом (≤ 120 символов, без точки в конце или заглавными) открывает раздел; `Clause.section` у всех последующих — его текст, например «3. Структура и организация работы внутреннего аудита». До первого раздела — `section="Преамбула"`.
4. Контекст пункта (решение аудита 1), всё детерминированно, в `parse/docx.py`:
   - `section_path: list[str]` — цепочка от раздела к родителям по номеру: для `5.9.1` это `["5. Права и обязанности", "5.9. Главный аудитор и работники БВА не имеют права:"]` (тексты родительских пунктов по их номерам, обрезай до 200 символов); для пункта первого уровня — только заголовок раздела; до первого раздела — `["Преамбула"]`. Родитель ищется по номеру (`5.9` для `5.9.1`), а не по соседству; если родителя с таким номером нет — цепочка короче, без выдумок.
   - `lead_in: str | None` — ближайший предшествующий абзац-вводная: (а) родительский пункт по номеру, если его текст оканчивается двоеточием («5.9. Главный аудитор и работники БВА не имеют права:», «2.4. … осуществляет следующие функции:»); (б) иначе ближайший выше абзац без номера в том же разделе, оканчивающийся двоеточием или короткий (≤ 80 символов) заголовок списка вида «Главный аудитор:», «Дополнительные требования:» — он действует на все последующие пункты до следующей вводной того же уровня или до следующего раздела. Нет такого — `None`. Сам абзац-вводная тоже остаётся пунктом (с номером или без) — цитаты не теряем.
   - `modality` — по словарю, сначала по `lead_in`, затем по собственному тексту пункта (собственный текст пункта важнее, если он содержит явный маркер): «не вправе», «не имеет права», «не имеют права», «запрещается», «не допускается» → `prohibition`; «имеет право», «имеют право», «вправе» → `right`; глаголы обязанности «осуществляет», «обеспечивает», «проводит», «формирует», «представляет», «организует», «обязан», «обязаны», «несёт/несут ответственность» → `duty`; иначе `neutral`. Словари вынеси в константы модуля (их переиспользует S09 для перепроверки `Function.modality`). Заголовки разделов и строки таблиц — всегда `neutral`.

ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ 34 ОГЛАВЛЕНИЕ 38 ПРИЛОЖЕНИЯ 38» — заглавный текст с числом страницы на конце после уже пройденного раздела с тем же номером. Такие строки в `clauses` не попадают. ## Дополнение по аудиту: структура реальных .docx (обязательно)

- Один абзац может содержать несколько пунктов подряд: «3.9. … 3.10.Работники … 3.11.…» (после номера пробела может не быть). Разбивай абзац на пункты по внутренним номерам вида `\d+(\.\d+)+\.` перед заглавной буквой или кавычкой.
- Буквенные подпункты «а.», «б.», «в.» … — отдельные адресуемые пункты: `clause_number` = номер родителя + буква (например `5.9.1.а`), `section_path` включает родителя, `lead_in` = текст родителя («…не имеют права:»).
- `clause_id` — стабильный адрес блока (`{doc_id}:p{индекс_абзаца}:{k}`), не зависящий от печатного номера; `clause_number` может быть `None`, тогда в отчёте показывается адрес блока и цитата — это честно и допустимо по ТЗ («фрагмент»).
- Разбор OOXML через `xml.etree.ElementTree` по `word/document.xml` в порядке блоков: `w:p` (абзацы, `w:numPr` → уровень списка), `w:tbl` (таблицы → строки «ячейка | ячейка» с адресом `t{n}:r{i}:c{j}`); текст из `w:t` с раскодированием сущностей (`&amp;` → `&`). `prebuilt/lib_docx.para_objs` можно использовать только как запасной путь: он теряет структуру таблиц и списков.
- Оглавление (строки «1. ОБЩИЕ ПОЛОЖЕНИЯ 1» с номером страницы в конце) отбрасывается по признаку «заглавные + число в конце».
- Тесты дополнительно: абзац с 3.9/3.10/3.11 даёт три пункта; «5.9.1.а» существует, его `lead_in` содержит «не имеют права», `modality == "prohibition"`; `get_clause(doc, "5.9.1.а")` возвращает текст «разрабатывать дизайн…».
