# S16 — Валидация входа и честные ошибки (волна 4, 16:00–16:40, B, ветка `s/validation`)

Прочитай `AGENTS.md` (правило 6 — ошибки и лимиты), `docs/case.md` (критерий «работоспособность», 25 баллов), `docs/spec-case11.md` §4 (формат ошибок `{error, detail}`, лимиты ≤ 10 файлов, ≤ 10 МБ, только .docx). Текущий роутер — `backend/app/routers/runs.py` (S08), разбор — `backend/app/prebuilt/lib_docx.py`; в `main.py` обработчики исключений добавлять нельзя, поэтому формат ошибки задаёт сам роутер.

**Пишешь только в:** `backend/app/validation.py`, `backend/tests/test_validation.py`.
В `backend/app/routers/runs.py` — **только добавление** проверки содержимого после сохранения и обёртки таймаута при запуске задачи (не переписывать существующие проверки и их коды ошибок).
**Не трогаешь:** `main.py`, `schemas.py`, `pipeline.py`, `store.py`, `llm.py`, `prebuilt/*`, модули шагов, фронт, чужие тесты. Новых зависимостей нет.

Задача: эксперт на своих файлах должен получать понятную русскую ошибку с полем и причиной, а не 500 и не зависший прогресс.

Сделай:
1. `validation.py`: `class UploadError(Exception)` с полями `field` (`before`/`after`/`files`/`run`), `reason`, метод `response() -> JSONResponse` со статусом 422 и телом `{"error": "validation", "detail": "<field>: <reason>"}`. Константы лимитов: `MAX_FILES=10`, `MAX_BYTES=10*1024*1024`, `PIPELINE_TIMEOUT_S=180` (переопределяются из `app.config`, если поля есть).
2. Проверки наличия групп, формата, количества и размера уже реализованы S08 в `_read_upload` с кодами `missing_documents`, `unsupported_format`, `too_many_files`, `file_too_large`. Не дублируй их и не вызывай `validate_upload` из роутера: эти коды должны сохраниться.
3. `validate_docx_content(path, field)` — файл открывается как zip и содержит `word/document.xml` (иначе «файл повреждён или это не документ Word»); текст не пустой; есть хотя бы один пункт с номером вида `1.4.` (через `lib_docx`, если доступен, иначе regex по тексту) — иначе «в документе нет нумерованных пунктов, разбор невозможен». Никаких LLM-вызовов.
4. `async def with_timeout(run_id, coro, store)` — оборачивает `run_pipeline`; по `asyncio.TimeoutError` пишет в store статус `error` с текстом «анализ превысил <N> с и остановлен; попробуйте меньше документов», любое другое исключение — тоже `error` с понятным текстом; процесс не падает.
5. Подключение в `routers/runs.py`: в `POST /api/runs` вызывай только `validate_docx_content` для каждого файла после сохранения; в `POST /api/runs/demo` — для комплекта. Сохрани коды и порядок существующих проверок S08. В `_create_run` замени `pipeline.start(run_id)` на `asyncio.create_task(with_timeout(run_id, pipeline.run_pipeline(run_id), store))` и держи ссылку на задачу в наборе до завершения, чтобы сборщик мусора её не удалил.
6. `tests/test_validation.py` (TestClient, `LLM_MODE=mock`, файлы генерируются в тесте через `zipfile`, без внешних фикстур), 5 случаев: `.pdf` → 422 с кодом `unsupported_format` и `detail` содержит «не поддержан»; файл 11 МБ → 422 с кодом `file_too_large` и «10 МБ»; случайные байты под именем `.docx` → 422 с «повреждён»; валидный zip с `document.xml` без пунктов → 422 с «нет нумерованных пунктов»; `with_timeout` с корутиной `asyncio.sleep` и таймаутом 0.1 с → статус run `error`, текст содержит «превысил». Все тела ошибок — ровно ключи `error` и `detail`. После изменений запусти также `uv run pytest -q tests/test_contract_smoke.py tests/test_runs.py`.

Числа лимитов в текстах ошибок брать из констант, не хардкодить. Ошибки — русский текст, без трейсбеков наружу.

**Done-when:** `cd backend && uv run pytest -q tests/test_validation.py`
**Cut-if:** проверка пунктов — только regex `^\d+(\.\d+)*\.` по тексту `document.xml`; таймаут тестируется без TestClient, напрямую на `with_timeout`.

В конце выведи список изменённых файлов и вывод Done-when.

  (например, в множестве модуля), чтобы её не собрал сборщик мусора.

## Режим работы: автономно, до зелёного Done-when

Ты работаешь в GUI, человек к тебе не вернётся до отчёта. Рабочая папка — worktree ветки `s/validation`.
Порядок: реализуй → **сам выполни команду Done-when** → красная: почини и повтори (до трёх попыток) →
зелёная: `git add -A && git commit -m "feat(S16): <что сделано>" && git push -u origin s/validation`.
Затем создай `status/agents/S16.md` в этом worktree: первая строка `# S16 — ЗЕЛЕНО` или `# S16 — КРАСНО`,
далее команда Done-when и её вывод, список изменённых файлов, что не сделано и почему; закоммить и запушь его так же.
Запреты: не пушить и не мержить в `main`; не трогать файлы вне своей строки матрицы владения; не добавлять зависимости;
не переписывать README и чужие тесты. После трёх красных попыток — отчёт «КРАСНО» с выводом ошибки и остановись.
