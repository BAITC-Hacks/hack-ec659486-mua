# S11 — Дубли и конфликты интересов (волна 3, 15:20–16:00, A, ветка `s/conflicts`)

**Пишешь только в:** `backend/app/duplicates.py`, `backend/app/rules/__init__.py`, `backend/app/rules/conflicts.py`, `backend/app/prompts/verify_duplicates.md`, `backend/app/prompts/explain_conflict.md`, `backend/app/mocks/verify_duplicates/**`, `backend/app/mocks/explain_conflict/**`, `backend/tests/test_conflicts.py`.
**Не трогаешь:** `main.py`, `schemas.py`, `llm.py`, `llm_schemas.py`, `candidates.py`, `matching.py`, `prebuilt/`, `pipeline.py`, чужие модули и тесты, фронт. Новых зависимостей нет.

Задача: `find_duplicates(functions_by_unit: dict[str, list[Function]], llm: LLM, candidate_pairs: list[tuple[Function, Function, float]] | None = None) -> list[Duplicate]` и `find_conflicts(functions_by_unit, llm, constraints: list[Function] | None = None) -> list[Conflict]` для одной версии документа (S08 вызывает их через `getattr` ровно с такими именами: `app.duplicates.find_duplicates`, `app.rules.conflicts.find_conflicts`; `candidate_pairs` он берёт из `app.candidates.find_duplicate_candidates` на шаге `candidates`). Каждая находка — с `sources` обеих функций, `verified: bool`, `verification: "llm"|"lexical"`, `verification_note`; без источника не возвращать. Функции с `modality == "prohibition"` — ограничения, а не функции: в дубли не идут, в конфликтах учитываются как контекст (запрет на действие снимает подозрение в его исполнении).

Принцип: сигнатура и любая похожесть — только **кандидат**, никогда не решение (известная коллизия: «аудит ИТ» и «аудит закупок» дают одну сигнатуру; порог косинуса — тоже не решение). Решает проверка LLM или узкое детерминированное правило с совпадением объекта.

Сделай:
1. `duplicates.py`. Кандидаты: если `candidate_pairs` передан — используй его; иначе ленивый `from app.candidates import find_duplicate_candidates` (пары функций **разных** подразделений одной версии, внутри одного подразделения не сравнивать, до 5 кандидатов на функцию); `ImportError` (S10 ещё не влит) → запасной генератор кандидатов внутри модуля только по равенству `signature` между разными `unit_id`, с `logger.warning("app.candidates недоступен, кандидаты только по сигнатуре")`. В любом случае перед поиском исключай шаблонные формулировки кодом: «иные функции», «поручения руководства», «согласно законодательству», «в пределах компетенции» и подобные (список констант `TEMPLATE_PHRASES` в модуле). Затем LLM `verify_duplicates` — **по одному вызову на пару-кандидат** (spec §5): system — `prompts/verify_duplicates.md` (по-русски: дубль — это **одно и то же действие над одним и тем же объектом у двух разных исполнителей**; не дубль, если одна из сторон «участвует», «содействует», «является соисполнителем» или просто ссылается на документ/регламент; ничего не выдумывать), user — JSON `{a:{id, unit, executor, modality, text, clause_number, section_path, lead_in}, b:{…}}`, schema — `strict_schema` модели `VerifyDuplicatesOut {is_duplicate: bool, same_action: bool, same_object: bool, both_executors: bool, verification_note: str}` (если S13 уже влил `llm_schemas.py` — брать оттуда, иначе своя модель с `extra="forbid"`). Проверка кодом: `is_duplicate=true` при любом ложном признаке (`same_action`, `same_object`, `both_executors`) — ответ невалиден, пара остаётся непроверенной. `is_duplicate=true` → `Duplicate(similarity=<оценка кандидата>, verified=True, verification="llm", verification_note=verification_note, sources=[…обеих функций])`; `is_duplicate=false` → пара не возвращается. Пары-кандидаты, для которых ответ проверки не получен (`LLMError`, невалидный ответ, превышен лимит `MAX_DUPLICATE_CALLS = 200` на версию) — `verified=False`, `verification="lexical"`, `verification_note="требует проверки: <причина>"`, отдельно от подтверждённых. Одинаковая сигнатура без подтверждения LLM — не дубль.
2. `rules/conflicts.py`. Сила контроля: `control_strength(text) -> "strong"|"weak"|None`: strong — «утверждает», «подписывает», «контролирует», «проверяет», «аудирует»; weak — только «согласовывает» (**weak — не находка**). Совпадение объекта обязательно: `object_overlap(f1, f2) -> float` по `object_head` и нормализованным словам объекта — контролирующая и исполняющая функции должны говорить об одном наименовании документа/объекта; без перекрытия пары нет. Исключения (функция `is_excluded(pair) -> str|None`, возвращает причину): «направляет на согласование/утверждение» (согласует или утверждает другой); контрольное слово внутри названия документа («акт проверки», «план контроля»); «участие в контроле», «содействие», «соисполнитель» на любой стороне; управленческий оборот «организация и контроль»; надзор за **чужим** исполнением (подрядчик, поставщик, документы других подразделений); собственное планирование и отчётность подразделения (годовой план аудита, отчёт о работе) — не операционная деятельность; «ссылается на документ ≠ производит документ». Правила, каждое — `(rule_id, title, role_pattern, check)` в `RULES`: (а) одно подразделение исполняет (`verb_class` СОЗДАВАТЬ/ОРГАНИЗОВЫВАТЬ/ВЕСТИ_УЧЁТ/ЭКСПЛУАТИРОВАТЬ) и strong-контролирует **один и тот же объект**; (б) одно подразделение инициирует («иницииру», «вносит», «предлага») и **утверждает** тот же объект (согласование — не утверждение); (в) подразделение внутреннего аудита (в названии «аудит») выполняет операционную функцию вне мандата аудита — закупает, начисляет, ведёт учёт, заключает договоры; (г) контроль возложен на контролируемого — объект strong-контрольной функции есть само подразделение, его руководитель или его собственные функции. Каждая находка: `rule_id`, `role_pattern` (например «исполнитель+контролёр», «инициатор+утверждающий», «аудитор+оператор», «самоконтроль»), `verified`, `verification_note`, `sources` обеих сторон.
3. LLM `explain_conflict` только для найденных пар: user — JSON `{rule_id, title, role_pattern, units, functions:[{id, unit, executor, modality, text, clause_number, section_path, lead_in}]}`, schema — `ExplainConflictOut {explanation: str, severity: low|medium|high, verified: bool, verification_note: str}` (spec §5; из `llm_schemas.py`, если S13 уже влит, иначе своя модель с `extra="forbid"`; `verified` — модель подтверждает, что это действительно совмещение несовместимых ролей над одним объектом). `verified=true` → `Conflict(verified=True, verification="llm", verification_note=…)`; `verified=false` → находка возвращается как кандидат: `verified=False`, `verification="lexical"`, `verification_note` от модели (почему сомневается) — в UI она пойдёт под «требует проверки»; ответ не получен (`LLMError`) → `verified=False`, `verification="lexical"`, `verification_note="требует проверки: объяснение не получено"`, `explanation` собирается кодом из `title` и цитат. `Conflict.sources` — из всех функций пары; номера пунктов в `explanation` не из переданных — удалять.

Mock-режим: при `llm.mode == "mock"` читай `mocks/<name>/<hash>.json`, `hash = sha256(json.dumps(user_payload, ensure_ascii=False, sort_keys=True))[:16]`; нет файла — `LLMError` с именем ожидаемого файла (для пары/находки это «нет ответа проверки» → `verified=False`, прогон не падает). Пустые кандидаты — LLM не вызывать. Фикстуры для тестовых случаев — в формате живого ответа, чтобы S15 заменил их реальными без правки кода.
5. `tests/test_conflicts.py` (`LLM_MODE=mock`, `Function` собирай руками с `executor`/`modality`, пункты «2.4.», «5.1.» и цитаты — дословно из `data/case11/*.txt`): дубль — одинаковое действие над одним объектом у двух подразделений с фикстурой `is_duplicate=true` → один `Duplicate(verified=True)`; та же сигнатура, но фикстура `is_duplicate=false` → пусто; «участвует в …» на одной стороне → не дубль; шаблон «иные функции» у двух подразделений → кандидатов нет, LLM не вызывается; внутри одного подразделения — ничего; «согласовывает акт» + «составляет акт» (weak, без утверждения) → не конфликт; «утверждает годовой план аудита» + «формирует годовой план аудита» у аудита → не конфликт (собственное планирование); «участие в контроле …» → исключено; «составляет акт X» + «утверждает акт X» в одном подразделении → `Conflict` с `rule_id="a"`, `role_pattern`, непустыми `sources`, `severity`, `verified=True`; правило (в) на «Блок внутреннего аудита» с «осуществляет закупки»; `modality="prohibition"` не даёт ни дубля, ни конфликта; фикстура `verify_duplicates` с `is_duplicate=true`, но `same_object=false` → пара остаётся `verified=False`; номер пункта в `explanation`, которого нет среди переданных, удалён; нет фикстуры → `LLMError` внутри, снаружи — находка с `verified=False` и причиной; пустой вход → пустые списки без вызова LLM (счётчик через monkeypatch). Кандидатов в тесте передавай через `candidate_pairs` — так тест зелёный и без `app.candidates`; отдельно проверь, что без `candidate_pairs` и без `app.candidates` модуль не падает (запасной генератор по сигнатуре).
